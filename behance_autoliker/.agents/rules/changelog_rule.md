# Правило: Обязательное ведение журнала изменений

## ⛔ КРИТИЧЕСКОЕ ПРАВИЛО — НЕ ИГНОРИРОВАТЬ

**После КАЖДОГО изменения кода** в этом проекте — **ОБЯЗАТЕЛЬНО** добавляй запись
в [`CHANGELOG.md`](../../CHANGELOG.md) в корне проекта.

Это правило применяется **всегда** и **без исключений**:
- при исправлении багов
- при добавлении функций
- при рефакторинге
- при изменении конфигурации
- при любом изменении поведения системы

**Запись в CHANGELOG должна быть последним шагом каждой задачи.**
Если ты не обновил CHANGELOG — задача не завершена.

---

## Формат записи

```markdown
## [YYYY-MM-DD HH:MM] — <Краткое название изменения>

**Причина:**
Описание проблемы или запроса, который привёл к изменению.
Если это баг — указать симптомы (что наблюдал пользователь).
Если это улучшение — описать цель.

**Изменено:** `имя_файла.py` — функция/класс/секция

- Пункт 1: что именно изменилось
- Пункт 2: ...

```python
# БЫЛО:
старый_код()

# СТАЛО:
новый_код()
```

**Результат:**
Что изменилось в поведении системы после правки.
Кратко: «было X → стало Y».

---
```

---

## Правила заполнения

1. **Причина** — обязательна. Без неё запись не имеет смысла.
2. **Изменено** — указывай конкретные файлы и функции, не «было изменено несколько файлов».
3. **Результат** — описывай наблюдаемое поведение, не технические детали.
4. **Новые записи** добавляются **вверху** списка (сразу после строки `---` под описанием формата).
5. **Дата/время** — локальное время пользователя в формате `YYYY-MM-DD HH:MM`.
6. Если изменение затронуло несколько файлов — описывай каждый отдельным подпунктом.
7. Не удаляй и не редактируй старые записи — только добавляй новые.
