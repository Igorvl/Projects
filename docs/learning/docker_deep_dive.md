# 🐳 Docker: Контейнеры, Образы и Multi-Stage Build

## Эфемерность контейнеров (главная ловушка новичка!)
Контейнер Docker — это **временный процесс**, а не виртуальная машина.

### Аналогия:
- **Docker Image (Образ)** = Рецепт торта (Dockerfile)
- **Docker Container (Контейнер)** = Испечённый торт (живой процесс)
- `docker compose build` = Испечь торт по рецепту
- `docker compose up -d` = Поставить торт на стол (запустить)
- `docker restart` = Торт остаётся тот же (перезапуск процесса)
- `docker compose up -d` (после изменения docker-compose.yml) = **ВЫБРОСИТЬ старый торт и испечь новый!**

### Почему `pip install` внутри контейнера пропадает?
```bash
docker exec ai-router pip install minio   # Ставим пакет в живой контейнер
# ... через час ...
docker compose up -d llm-router           # Docker ПЕРЕСОЗДАЁТ контейнер из ОБРАЗА
# Образ не знает про minio → пакет пропал! 💀
```

**Правильный способ:** Добавить пакет в `requirements.txt` + пересобрать образ:
```bash
echo "minio" >> routing/requirements.txt
docker compose build llm-router     # Образ теперь ВКЛЮЧАЕТ minio навсегда
docker compose up -d llm-router     # Новый контейнер из нового образа
```

## Multi-Stage Build (Многоступенчатая сборка)

### Зачем?
Для компиляции Python-пакетов нужны `gcc`, `build-essential` (~200 МБ).
В продакшене эти инструменты не нужны. Multi-stage позволяет:
1. **Стадия Builder:** Установить `gcc`, скомпилировать всё
2. **Стадия Runtime:** Взять чистый `python:slim`, скопировать только результат

### Пример из нашего Dockerfile.router:
```dockerfile
# Стадия 1: Тяжёлый строитель
FROM python:3.12-slim as builder
RUN apt-get install build-essential    # 200 МБ инструментов компиляции
RUN pip install -r requirements.txt    # Компилируем C-расширения

# Стадия 2: Лёгкий финальный образ
FROM python:3.12-slim                  # ЧИСТЫЙ образ без build-essential
RUN apt-get install ffmpeg             # Только runtime-зависимости!
COPY --from=builder /root/.local ...   # Копируем ТОЛЬКО Python-пакеты
```

### Ловушка: Системные пакеты не копируются!
`COPY --from=builder` копирует только файлы, а не установленные apt-пакеты.
Если `ffmpeg` стоял только в builder-стадии, в финальном образе его НЕ БУДЕТ!
**Решение:** Ставить runtime-зависимости прямо в финальной стадии.

## Полезные команды Docker:

| Команда | Что делает |
|---------|-----------|
| `docker ps` | Список запущенных контейнеров |
| `docker logs --tail 20 NAME` | Последние 20 строк логов |
| `docker logs -f NAME` | Логи в реальном времени (Ctrl+C для выхода) |
| `docker exec NAME cmd` | Выполнить команду внутри контейнера |
| `docker exec --user root NAME cmd` | Выполнить от рута (для pip install) |
| `docker restart NAME` | Перезапустить без пересоздания |
| `docker compose up -d` | Запустить/пересоздать сервисы |
| `docker compose build SERVICE` | Пересобрать образ сервиса |
| `docker compose down` | Остановить и удалить все контейнеры |

## Переменные окружения (Environment Variables):
Секреты (пароли, API-ключи) передаются через `environment:` в docker-compose.yml.
Значения берутся из файла `.env`:
```yaml
environment:
  - GEMINI_API_KEY=${GEMINI_API_KEY}     # Берёт из .env
  - MINIO_ACCESS_KEY=${MINIO_USER}       # Берёт из .env
  - HF_HOME=/app/models                  # Захардкожено (не секрет)
```

`.env` файл добавлен в `.gitignore` — секреты НИКОГДА не попадают в Git!

## 📂 Блок `volumes:` — почему он встречается дважды?

### 1. Внутри сервиса (например, под `llm-router:`)
Здесь мы прописываем **привязки (маппинги)** для конкретного контейнера. Формат: `ОТКУДА : КУДА`.
Привязки бывают двух типов:
* **Bind Mount** (например, `- ../routing:/app/routing` или `- ./antigravity.json:/app/...`) — мы указываем конкретный путь к реальной папке на твоём компьютере. Docker просто "протыкает" дыру из хост-системы внутрь контейнера.
* **Именованный том (Named Volume)** (например, `- pg_data:/var/lib/postgresql/data`) — мы не указываем путь на диске, а говорим: *"Docker, возьми диск с именем `pg_data` и подключи его"*.

### 2. В самом конце файла (корневой `volumes:`)
Именованные тома (Named Volumes) — это виртуальные флешки, которыми управляет сам Docker Engine (они хранятся где-то глубоко в его системных папках). 
По правилам синтаксиса `docker-compose.yml`, все "виртуальные флешки", которые упоминаются в файле, **обязаны быть объявлены в глобальном списке в самом конце файла**.
```yaml
# Декларация: "Докер, убедись, что такие виртуальные диски существуют"
volumes:
  qdrant_data:
  pg_data:
  minio_data:
```
Если ты подключишь `pg_data` к базе Postgres, но забудешь объявить его в конце файла, Docker Compose выдаст ошибку во время запуска. А вот директории с твоего диска (Bind Mounts) вроде `../routing` в конце файла упоминать не нужно!

## 🔄 Как применить изменения в коде (Python)?

Один из самых частых вопросов: *"Я изменил `router.py`, нужно ли мне делать `docker compose up -d`?"*

Ответ зависит от того, **как файлы лежат в контейнере**:

### Сценарий А. Код проброшен через Volume (режим разработки)
Если в твой `docker-compose.yml` прописано что-то вроде:
```yaml
volumes:
  - ./routing:/app/routing
```
Это значит, что контейнер читает файл **напрямую с твоего диска**. 
* Твои изменения в `router.py` уже внутри контейнера!
* Но сам Python-процесс (FastAPI) загрузил старый код в оперативную память при старте.
* **Что делать:** Тебе нужно просто **перезапустить процесс**:
  ```bash
  docker compose restart ai-router 
  # или 
  docker restart <имя_контейнера>
  ```
* *(Примечание: Если запускать uvicorn с флагом `--reload`, даже рестарт не нужен — он сам перезагрузится).*

### Сценарий Б. Код "запечён" в образ (режим продакшена)
Если `Volume` не используется, а в `Dockerfile` написано `COPY . /app` — значит код был скопирован внутрь образа в момент его сборки. Изменение файла на сервере **никак не влияет** на запущенный контейнер!
* **Что делать:** Нужно дать команду Docker'у заново прочитать изменённый файл, собрать новый "рецепт" (образ) и пересоздать контейнер:
  ```bash
  docker compose up -d --build <имя_сервиса>
  ```
  *(Флаг `--build` критически важен, без него `up -d` скажет "Всё и так работает" и ничего не сделает).*
