# ESXi: Настройки CPU и Nested Virtualization

> 📚 Возникало в ходе подготовки сервера для macOS Build Agent'а.

В VMware vSphere Web Client при редактировании параметров CPU виртуальной машины (VM) есть скрытый блок дополнительных настроек. Понимание этих трех параметров критически важно для MLOps и DevOps инженеров при настройке сложных контейнерных (Docker/KVM) сред.

---

## 1. Hardware virtualization
**`Expose hardware assisted virtualization to the guest OS`**

* **Что это:** Проброс инструкций Intel VT-x или AMD-V внутрь виртуалки. "Вложенная виртуализация" (Nested Virtualization).
* **Суть работы:** Обычно гипервизор абстрагирует физический процессор от виртуальной машины, делая его "обычным". Если поставить эту галочку, гипервизор передаст внутрь гостевой ОС знания о том, что процессор умеет вплетаться в гипервизоры.
* **Для чего включать:** Если внутри вашей Ubuntu-машины вы хотите запустить Docker-контейнеры, базирующиеся на KVM (например, QEMU или `sickcodes/Docker-OSX`).
* **Что будет, если не включить:** Все вложенные системы будут использовать программную эмуляцию процессора (Software Emulation, TCG). Это снижает скорость работы программ в сотни раз (macOS будет загружаться часами).
* **Проверка:** Внутри Ubuntu сработает команда `kvm-ok` (покажет `KVM acceleration can be used`).

---

## 2. IOMMU
**`Expose IOMMU to the guest OS`**

* **Что это:** Проброс инструкций Intel VT-d (или AMD-Vi). I/O Memory Management Unit.
* **Суть работы:** PCI Passthrough ("проброс устройств"). Эта технология позволяет гипервизору изолировать шину PCI на материнской плате сервера так, чтобы виртуальная машина обращалась к железу НАПРЯМУЮ, минуя слой драйверов хост-ОС (ESXi).
* **Для чего включать:** В системах типа MLOps — это основа проброса физических видеокарт (NVIDIA A100/Tesla/RTX) внутрь виртуалки для обучения нейросетей, либо проброс аппаратных RAID-контроллеров и скоростных NVMe дисков напрямую.
* **Что будет, если не включить (и попытаться пробросить устройство):** Вы не сможете отдавать физические железки вашим докер-контейнерам или дочерним виртуальным машинам.
* **Нужно ли нам сейчас:** Нет, для запуска виртуального CPU и виртуального диска (чистый Docker-OSX) прямой доступ к шине PCI не используется.

---

## 3. Performance counters
**`Enable virtualized CPU performance counters`**

* **Что это:** PMCs (Performance Monitoring Counters).
* **Суть работы:** Раскрывает низкоуровневые регистры процессора гостевой ОС, которые считают аппаратные метрики в режиме реального времени (например, количество тактов CPU, промахи L1/L2/L3 кэша, ошибки предсказателя переходов).
* **Для чего включать:** Используется хардкорными разработчиками на C++/Rust, которые разрабатывают высоконагруженные движки и микросервисы (HFT/трейдинг/игровые движки) и используют профилировщики `perf` (в Linux) или Intel VTune Amplifier.
* **Что будет, если не включить:** Профилировщики покажут только уровень софта, но не смогут видеть "затыки" на уровне транзисторов и P-core/E-core процессора.
* **Нужно ли нам сейчас:** Нет. Более того, включение счетчиков иногда мешает vMotion (живой миграции виртуалки между хостами в кластере VMWare), потому что требует точного совпадения микрокода CPU на обеих машинах.
