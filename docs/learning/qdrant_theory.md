# 🎯 Векторные базы данных и Qdrant

Векторная база данных — это основа работы RAG (Retrieval-Augmented Generation) и семантического поиска. Вы только что убедились в этом сами: вектор `[0.15, 0.25, 0.35, 0.45]` успешно нашел "красный спорткар" и "красную феррари", потому что их векторы были математически близки!

## 🧠 Как работает поиск по смыслу:

1. **Embedding (Векторизация):** ML-модель берет текст и превращает его в большой массив чисел (вектор), например, из 1536 измерений (или 384, как часто бывает в локальных моделях).
2. **Хранение в Qdrant:** Этот вектор сохраняется в БД. Вместе с ним мы сохраняем **Payload** — мета-информацию в формате JSON (ID проекта, исходный текст, параметры генерации).
3. **Similarity Search (Поиск):** При поиске мы векторизуем запрос пользователя и просим Qdrant: *"Найди N ближайших векторов в этом многомерном пространстве"*.
4. **Distance (Математика):** Близость обычно считается с помощью косинусного расстояния (`Cosine Distance`). Если векторы направлены в одну сторону, их косинус близок к 1 (максимальное совпадение по смыслу).

## 🛠 Ключевые понятия Qdrant:
- **Collection (Коллекция):** Аналог "Таблицы" в традиционном SQL. Все векторы в одной коллекции обязаны иметь одинаковую длину (`size`). У нас это будет, например, коллекция `prompts`.
- **Point (Точка):** Одна запись в коллекции. Она состоит из обязательного `id`, самого `vector` и `payload`.
- **Payload (Полезная нагрузка):** JSON-словарь, который хранится вместе с вектором. По payload можно делать обычные `WHERE`-фильтры (в терминологии Qdrant это `Filter`) прямо во время векторного поиска. Например: "найди похожие промпты, но только где `project_id = 5`".
