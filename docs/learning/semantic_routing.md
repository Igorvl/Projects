# 🧭 Семантическая Маршрутизация (Semantic Routing)

## Что это и зачем?

**Semantic Router** — это компонент, который автоматически определяет,
к какому **проекту/категории** относится входящий текст, не требуя
ни одного обучающего примера. Это альтернатива ручному выбору проекта.

### Аналогия
Представь умного почтальона. Он видит письмо, читает первые строки,
и СРАЗУ кладёт его в нужный ящик (проект). Он не знаком лично с каждым
отправителем — он просто понимает контекст письма.

---

## Zero-Shot Classification

**Zero-Shot** = классификация БЕЗ обучающих примеров.

| Подход | Нужно данных | Качество | Скорость запуска |
|--------|-------------|---------|-----------------|
| Supervised ML | 1000+ размеченных примеров | ★★★★★ | Медленно (дни) |
| Few-Shot | 5-20 примеров | ★★★★☆ | Быстро (часы) |
| **Zero-Shot (наш)** | 0 примеров | ★★★☆☆ | Мгновенно |

Наш подход: мы даём LLM (Gemini Flash Lite) **описание проектов**,
и он сам понимает, куда отнести каждый промпт.

```
Система говорит LLM:
"Есть проекты:
 - ksar-me (Название: Ksar.me Design)
 - audiobook (Название: Audiobook Generator)

К какому проекту относится этот текст?"

Пользователь: "Сделай кнопку с hover-анимацией для лендинга"

LLM отвечает: "ksar-me"
```

## MD5 Кэширование

### Зачем кэш?
Каждый вызов LLM стоит времени (~1-2сек) и денег (токены).
Если пользователь отправляет 50 сообщений в одном чате — нет смысла
для каждого делать новый API-вызов. Проект определили один раз → всё!

### Как работает MD5
MD5 — это hash-функция. На вход любая строка, на выход — 32 символа.

```python
import hashlib
text = "Сделай кнопку с hover-анимацией"
hash = hashlib.md5(text.encode('utf-8')).hexdigest()
# hash = "a1b2c3d4e5f6..." (32 символа, всегда один для одного текста)
```

**Ключевое свойство:** Одинаковый текст → всегда одинаковый MD5.
Так мы "помним" к какому проекту относится конкретный первый запрос.

### Ограничение
`ROUTING_CACHE = {}` — это словарь в памяти. При рестарте контейнера — пропадает.
Для production нужен Redis. Но для нашего масштаба — достаточно.

---

## Temperature = 0.0: Почему?

В LLM `temperature` управляет "случайностью" ответа:
- `temperature=1.0` — творческий, разнообразный (хорошо для генерации текста)
- `temperature=0.0` — детерминированный, стабильный (хорошо для классификации)

Для роутера нам нужна **стопроцентная стабильность**:
"ksar-me" сегодня = "ksar-me" завтра для одного и того же промпта.

---

## Почему Gemini 2.5 Flash LITE?

Задача роутинга простая — просто выбрать из списка. Не нужна умная модель.
Lite-модели в 5-10 раз дешевле и быстрее полных:

| Модель | Стоимость на 1M токенов | Latency |
|--------|-------------------------|---------|
| Gemini 1.5 Pro | $7 | ~3s |
| Gemini 2.0 Flash | $0.15 | ~1s |
| **Gemini 2.5 Flash Lite** | **~$0.05** | **~0.5s** |

## Confidence vs UNKNOWN

Наш роутер не возвращает числовую вероятность — LLM просто отвечает
слагом или "UNKNOWN". Это упрощение, но надёжное:

- **Определил проект** → `project_slug = "ksar-me"`
- **Не уверен** → `project_slug = null` → Extension ставит в очередь

## Баги и Ловушки

### Баг: `logger` не импортирован
В `semantic_router.py` есть строка `logger.info(...)`, но `logger` нигде
не объявлен. При ошибке это вызовет `NameError`. Нужно заменить на `print()`.

### Ловушка: регистр slug
LLM может ответить "Ksar-Me" вместо "ksar-me". Решение:
конвертируем ответ в `.lower()` и ищем совпадение без учёта регистра.

### Ловушка: изображения при авто-роутинге
Когда Extension загружает изображение в MinIO, ей нужен `project_slug`
для пути (например: `ksar-me/gen-001/image.png`).
При авто-роутинге проект неизвестен заранее.
**Решение:** Сохранять оригинальный Google URL в базе (как fallback),
MinIO-загрузку делать после определения проекта.
