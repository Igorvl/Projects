# 🗄️ Базовые команды SQL: Разница между DDL и DML

При работе с базами данных (например, PostgreSQL) все команды SQL можно условно разделить на две большие категории: **DDL** (работа со структурой) и **DML** (работа с данными).

---

## 🏗️ 1. DDL (Data Definition Language) — Язык описания данных
Эти команды используются для создания, изменения и удаления самих таблиц, баз данных и их структур (колонок).
Подсказка из Adminer (SELECT, INSERT, UPDATE) не предлагает эти команды, так как они используются реже (только при проектировании или обновлении архитектуры, что называется **миграциями**).

**Ключевые команды DDL:**
* `CREATE` — Создать новую таблицу, базу данных или индекс.
  * *Пример:* `CREATE TABLE users (id INT, name VARCHAR);`
* `ALTER` — Изменить существующую таблицу (например, добавить или удалить колонку).
  * *Пример:* `ALTER TABLE users ADD COLUMN age INT;`
* `DROP` — Полностью удалить таблицу или базу данных (опасно!).

### Разбор миграции Project DNA

```sql
ALTER TABLE generations 
ADD COLUMN IF NOT EXISTS source VARCHAR(50) DEFAULT 'extension',
ADD COLUMN IF NOT EXISTS metadata JSONB DEFAULT '{}';

CREATE INDEX IF NOT EXISTS idx_generations_source ON generations(source);
```

**Что здесь происходит:**
1. `ALTER TABLE generations` — мы приказываем базе изменить структуру таблицы `generations`.
2. `ADD COLUMN IF NOT EXISTS source` — добавить новую колонку с именем `source` (если её еще нет).
3. `VARCHAR(50)` — тип данных: строка длиной до 50 символов.
4. `DEFAULT 'extension'` — значение по умолчанию. Все старые записи в этой таблице автоматически получат значение `'extension'`. Если не указывать значение явно при добавлении новой строки, система тоже подставит `'extension'`.
5. `metadata JSONB` — особый тип данных в Postgres, позволяющий хранить сложные JSON-объекты (словари/массивы) прямо внутри одной ячейки таблицы в бинарном и индексируемом формате.
6. `CREATE INDEX ... ON generations(source)` — создание индекса. Индекс работает как оглавление в конце энциклопедии. Когда мы в будущем попросим базу: "Дай мне все диалоги, где `source='open-webui'`", база не будет построчно перебирать 100 000 строк (Full Table Scan), а моментально прыгнет в нужные места по индексу.

## 📝 2. DML (Data Manipulation Language) — Язык манипулирования данными
Эти команды используются для ежедневной работы с "содержимым" таблиц — строками. И именно их тебе подсказывал интерфейс Adminer.

**Ключевые команды DML:**
* `SELECT` — Получить/прочитать данные (ничего не меняет в базе).
  * *Пример:* `SELECT * FROM generations LIMIT 10;`
* `INSERT INTO` — Вставить новую строку с данными в таблицу. Обычно это делает приложение "под капотом".
* `UPDATE` — Изменить данные в существующих строках.
  * *Пример:* `UPDATE generations SET source = 'api' WHERE id = 5;`
* `DELETE FROM` — Удалить строки из таблицы.

## 💡 Как выполнять DDL команды (ALTER, CREATE) в Adminer
В окне "SQL command" интерфейс Adminer просто предлагает быстрые шаблоны DML. Но окно поддерживает **абсолютно любые** формы SQL.

Для выполнения DDL (например, `ALTER TABLE`):
1. Скопируй весь блок SQL-кода.
2. Вставь его напрямую в большое текстовое поле (игнорируя всплывающую подсказку `SELECT / INSERT`).
3. Убедись, что выбрана правильная база (`DB: project_dna`) и схема (`Schema: public`).
4. Нажми кнопку **Execute** (или `Выполнить`) под текстовым полем.
5. Команды будут выполнены последовательно (разделены символом `;`).
6. После успеха появится зеленая плашка, и структура таблицы мгновенно обновится.
