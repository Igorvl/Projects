# 📖 Словарь терминов MLOps и Архитектуры

## API (Application Programming Interface)
**Программный интерфейс приложения.**
Представьте себе ресторан:
- **Кухня** = сервер (наш Роутер с базами данных, сложной логикой).
- **Посетитель** = клиент (например, Браузерное расширение Safari или веб-сайт).
- **Меню и Официант** = это и есть **API**. 

Посетитель не идет на кухню готовить сам (клиент не выполняет код базы данных). Он смотрит в меню (документацию API), говорит "хочу блюдо номер 5" (отправляет HTTP-запрос по строгому правилу, например `POST /v1/dna/capture`), а кухня потом возвращает приготовленную еду (структурированный JSON-ответ).
Таким образом, **API — это розетка/порт подключения для других программ**. Программы не умеют кликать мышкой по экрану, они общаются друг с другом через API.

## Пайплайн (Pipeline)
**Конвейер (или "прямая труба").** 
Вы угадали на 100%. Это цепочка выполнения действий (модулей), где выход (output) одного шага жестко становится входом (input) для следующего шага. Как на заводе Форда: кусок металла -> плавка -> штамповка -> покраска -> готовая деталь.

### Примеры из нашего проекта:
1. **TTS Pipeline (Конвейер озвучки)**: 
   Сырой текст -> разбивка на чанки (по 3000 символов) -> отправка в Chatterbox -> возврат сырого аудио -> сохранение 100 файлов на диск -> склейка через ffmpeg -> готовый MP3.
   *(Именно на этом конвейере у нас были затыки, когда "станок" Chatterbox перегревался и роутер выкидывал ошибку).*
   
2. **RAG Pipeline (Генерация с дополненной памятью)**:
   Дизайнер написал промпт -> Роутер получил промпт (через API) -> записал как текст в базу PostgreSQL -> преобразовал текстовый промпт в набор цифр-вектор (Fastembed) -> сохранил этот вектор в базу Qdrant.
