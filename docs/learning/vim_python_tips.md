# 🖊️ Vim + Python: Практические Заметки

## Почему vim важен для DevOps/MLOps?

На production-серверах нет VS Code, нет GUI. Только терминал.
`vim` (или `nano`) — единственный инструмент редактирования.
Умение быстро редактировать файлы прямо на сервере = критичный DevOps-скилл.

---

## 🔑 Базовые режимы vim

vim — это НЕ обычный редактор. Он работает в режимах:

| Режим | Как войти | Для чего |
|-------|-----------|---------|
| **Normal** | `Esc` | Навигация, команды |
| **Insert** | `i`, `o`, `O`, `a` | Написание текста |
| **Visual** | `v`, `V`, `Ctrl+V` | Выделение |
| **Command** | `:` | Сохранение, поиск, замена |

**Главное правило:** если что-то идёт не так — жми `Esc` несколько раз.

---

## 🧭 Навигация (Normal mode)

```
gg      — в начало файла
G       — в конец файла
:42     — перейти на строку 42
/текст  — поиск вперёд (n = следующее, N = предыдущее)
?текст  — поиск назад
0       — начало строки
$       — конец строки
w       — на слово вперёд
b       — на слово назад
```

---

## ✏️ Редактирование (Normal → Insert)

```
i       — вставить ПЕРЕД курсором
a       — вставить ПОСЛЕ курсора
o       — новая строка НИЖЕ текущей (копирует отступ!)
O       — новая строка ВЫШЕ текущей
cc      — удалить строку и войти в Insert mode
dd      — удалить строку (без Insert)
yy      — скопировать строку
p       — вставить скопированное
u       — отменить (undo)
Ctrl+R  — повторить (redo)
```

---

## 💾 Сохранение и выход

```
:w      — сохранить (write)
:q      — выйти
:wq     — сохранить и выйти (самая частая команда!)
:q!     — выйти БЕЗ сохранения (если накосячил)
:wq!    — принудительно записать и выйти
```

**Мнемоника:** `:wq` = "write, quit"

## 🐍 Критически важно для Python: Отступы

Python — единственный язык, где отступы являются синтаксисом.
Одна лишняя пробела = `IndentationError` = сервер не запускается.

### Проблема вставки в vim

При обычной вставке (Shift+Ins или Ctrl+Shift+V) vim пытается
"помочь" — добавляет отступы автоматически. Результат:

```python
try:
    x = 1
        y = 2   # vim добавил лишний отступ при вставке!
        z = 3   # IndentationError!
```

### Решение: `:set paste`

```
:set paste      — ВЫКЛЮЧИТЬ авто-форматирование
i               — войти в Insert mode
[Вставить код]  — вставлять как есть, без изменений
Esc
:set nopaste    — вернуть авто-форматирование
:wq             — сохранить
```

**Это стандартная практика** при работе с Python в vim!

## 🔍 Полезные команды для дебага Python-файлов

```bash
# Показать строки 55-75 файла с номерами
sed -n '55,75p' /path/to/file.py

# Показать строки с ВИДИМЫМИ пробелами/табами
sed -n '55,75p' /path/to/file.py | cat -A
# ^I = Tab, пробел = пробел, $ = конец строки

# Проверить синтаксис Python БЕЗ запуска
python3 -m py_compile /path/to/file.py
echo $?  # 0 = ОК, не-0 = ошибка синтаксиса

# То же самое с читаемой ошибкой
python3 -c "import py_compile; py_compile.compile('/path/to/file.py')"
```

## ⚠️ Python UnboundLocalError — Частая Ловушка

```python
def check():
    print(x)         # ← UnboundLocalError! Python видит x = ... ниже
    x = 42           # ← Python знает, что x будет локальной
    print(x)         # ← только здесь OK
```

**Почему:** Python анализирует всю функцию ПЕРЕД выполнением.
Если видит `x = ...` где-то в теле → `x` помечается как локальная.
Обращение к локальной переменной ДО её присвоения = `UnboundLocalError`.

**Пример из нашего проекта:**
```python
# ❌ НЕПРАВИЛЬНО:
detected_slug = res.choices[0]...
print(f"slug: {detected_slug} | valid: {valid_slugs_lower}")  # UnboundLocalError!
valid_slugs_lower = [...]   # ← определена позже, но Python уже "знает"

# ✅ ПРАВИЛЬНО:
detected_slug = res.choices[0]...
print(f"slug: {detected_slug}")  # только то, что уже определено!
valid_slugs_lower = [...]
print(f"valid: {valid_slugs_lower}")  # теперь OK
```

## 🛠️ Патчинг файла через Python (безопаснее vim для точечных замен)

Когда нужно заменить конкретную строку — Python-однострочник
надёжнее чем vim sed, особенно со спецсимволами:

```bash
python3 -c "
path = '/path/to/file.py'
with open(path) as f: content = f.read()
fixed = content.replace('старый текст', 'новый текст')
with open(path, 'w') as f: f.write(fixed)
print('Done!')
"
```

**Плюсы:** Нет проблем с экранированием в sed, нет рисков с отступами.
**Минусы:** Работает только при уникальном вхождении строки.

## 📋 Чек-лист перед рестартом контейнера

После правки Python-файла на сервере:

```bash
# 1. Проверить синтаксис
python3 -m py_compile файл.py && echo "OK" || echo "SYNTAX ERROR"

# 2. Рестартовать
docker restart ai-router

# 3. Проверить что запустился (нет ImportError, SyntaxError)
docker logs --tail 20 ai-router | grep -E "Error|Exception|startup complete"
```

Если видишь `Application startup complete.` — файл загрузился без ошибок.
Если видишь Traceback → читай первую строку `File "..." line N` — это точка входа ошибки.
